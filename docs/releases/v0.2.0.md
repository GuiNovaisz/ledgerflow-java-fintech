# LedgerFlow v0.2.0 — Full Stack

**Status: preparado localmente; não publicado. / Prepared locally; not published.**

## Português (Brasil)

O LedgerFlow evolui do backend v0.1.0 para uma aplicação Full Stack com React/TypeScript, mantendo a API bearer, a integridade do ledger e a release anterior.

### Entrega

- Dashboard de dados reais: saldos, fluxo de caixa, evolução diária, categorias e movimentações recentes.
- Cadastro/login/logout por sessão HttpOnly, token CSRF em memória e isolamento da cadeia bearer existente.
- Contas, detalhes, status, extrato filtrado/paginado e CSV; depósitos, saques e transferência em três etapas.
- Consulta de operação por chave e recuperação após resultado incerto, sem repetir uma cobrança com chave nova.
- Metas manuais completas com owner isolation, migration V2 e conflito de versão; sem reserva de dinheiro.
- Temas claro/escuro/sistema, PT-BR/EN, desktop/mobile, estados vazios e tratamento de erros.
- Compose com frontend Nginx sem root, demo sintética opcional, pipeline ampliado e documentação educacional.

### Validação

51 testes Java (29 unitários + 22 integrações PostgreSQL), 13 testes Vitest, 6 jornadas E2E e 1 cenário de captura visual aprovados localmente. Lint, TypeScript, builds e reconciliação de dados passaram. Sete screenshots reais estão no README. Auditoria npm: zero achados. OSV: 141 dependências, dois avisos condicionais Spring já revisados, sem novos avisos pendentes. Veja [evidências](../verification-v0.2.0.md).

### Compatibilidade e limites

Rotas antigas e V1 são preservadas; V2 acrescenta metas. Sessões de navegador são perdidas ao reiniciar o servidor. Metas são planejamento manual. O seed histórico é explícito, local e somente para demonstração. BRL, CSV limitado e UTC continuam sendo escolhas do domínio. Nenhum dinheiro real, banco ou pagamento é integrado.

CI remoto desta versão, merge, push final, tag anotada e GitHub Release aguardam autorização explícita do proprietário. Não existe deploy público automático. Após a autorização, reconferir a branch remota, validar o commit integrado e confirmar os resultados remotos antes de declarar a release publicada.

## English

LedgerFlow grows from the v0.1.0 backend into a React/TypeScript full stack application while retaining the bearer API, ledger invariants and the previous release.

### Delivery

- Database-backed dashboard with balances, cash flow, daily trends, categories and recent postings.
- HttpOnly browser sessions, in-memory CSRF tokens, server-side logout and isolation from the legacy bearer chain.
- Accounts, detail/status controls, filtered/paginated statements and CSV; simulated deposits, withdrawals and three-step transfers.
- Operation lookup by key and recovery from uncertain outcomes without creating a new charge attempt.
- Owner-scoped manual-goal CRUD, V2 migration and version conflicts; goals do not reserve funds.
- Light/dark/system themes, Portuguese/English, desktop/mobile layouts, empty and error states.
- Unprivileged Nginx frontend in Compose, optional synthetic demo, expanded CI and educational documentation.

### Verification

51 Java tests (29 unit + 22 PostgreSQL integration), 13 Vitest tests, 6 E2E journeys and 1 visual-capture scenario passed locally. Lint, TypeScript, builds and data reconciliation passed. Seven real screenshots are linked from the README. npm audit found no advisories. OSV covered 141 dependencies with two previously assessed conditional Spring advisories and no new unresolved findings. See [evidence](../verification-v0.2.0.md).

### Compatibility and limitations

Legacy routes and V1 are retained; V2 adds goals. Browser sessions disappear on backend restart. Goals are manually tracked planning. Historical seeding is explicit, local and demo-only. BRL, bounded CSV export and UTC reporting remain intentional constraints. No real funds, banks or payment rails are involved.

Remote CI for this version, merge, final push, annotated tag and GitHub Release await explicit owner approval. There is no automatic public deployment. After approval, recheck the remote branch, validate the integrated commit and confirm remote results before reporting publication.
